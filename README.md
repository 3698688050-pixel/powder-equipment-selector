# 粉体设备高级预选型

输入物料、产能、目标粒度和工艺属性，输出 Top3 设备方案；结果页可一键导出这 3 条为 PDF。
纯单页工具，无框架、无后端、无外部字体，断网也能用。

## 在线使用

**https://3698688050-pixel.github.io/powder-equipment-selector/**

打开即用，手机和桌面都适配。想让同事也能用，把这个网址发过去就行；需要离线留档时下载 `index.html` 双击打开。

## 怎么填

| 区块 | 填什么 | 说明 |
|---|---|---|
| 01 物料与产能 | 物料名称（可从 1433 条库选，也可手填）、产能 kg/h | 手填时按名称 / 别名 / 英文名 / CAS 号去库里匹配，匹配不到自动降级为通用先验 |
| 02 粒度标准 | 目标粒径 + 分布（D50/D90/D97/D99/D100）、单位（µm / 目）、入料粒度 | 入料粒度可不填，不填时粉碎比按中性处理 |
| 03 物理与工艺属性 | 13 项开关：莫氏硬度高、磨蚀性极强、含水率高、纤维 / 高韧性、粘性易糊壁、易起静电、流动性差、热敏 / 低熔点、易氧化、易挥发、易燃易爆、无金属污染、医药食品级 | 勾选会改变机型与防护配置；只有勾了「易燃易爆」才出现防爆强制提示 |

## 结果怎么读

每张结果卡自上而下：**机型图**（该族有样册图的才显示）、**推荐型号 + 匹配度**、规格表（可达粒度 / 单机产能 / 分级方式等）、**推荐理由**一条。

推荐理由不给百分比，只给能对得上的数：

```
最符合 · 可达 D97 5–45 µm · 单机 300–5000 kg/h · 粉碎比 300
次选   · 可达 D50 2–150 µm（D50 口径，与你填的 D97 不同） · 单机 200–3000 kg/h
```

- 粒度区间直接取设备库，括号里注明是「系列范围」还是「口径不同」——拿 D50 区间回答 D97 的问题，懂行的客户一眼能看出来，所以宁可自己先说。
- 样册没列产能的族写「样册未列产能，按物料与细度核定」，不编一个「产能匹配 90%」上去：客户一问「90% 怎么算的」就答不上来。
- 匹配度百分比只出现在卡片角标，它是排序分的归一化结果，不是实验结论，排序的可靠性见下方「注意边界」。

机型图来自官网样册，已洗白底色、去掉棚拍水印、按主体裁边（`tools/white-bg.py`），33 个族有图，其余族不出图、卡片直接收起图片区，不留空框。

下面「参考成交案例」按**物料 / 粒度 / 产量**三个维度做最近邻检索，只列同料（或同料族）的案例，每条带时间。时间只到年份：官网只给了站内上线批次，没有逐条成交日期，精确到月等于编精度。

**导出 PDF**：结果区右上角「导出 PDF（前 3 名）」，只导出这 3 张推荐卡 + 一行免责声明，不含输入区与案例列表，压在一页 A4 内（打印样式按 mm 排版，纸张尺寸写死在 `@page`，浏览器边距不影响）。

公司名称不在表单里，点「导出」才弹一次框问：它是给客户看的抬头，不是选型参数，放在顶部只会让人以为必填。名称校验在弹框内做（纯空格 / 全角空格一律算没填，只在字段下标红，不弹打印框），填过会存 `localStorage`，下次不用重填。名称拼在页眉「粉体预选型 v11.1」之后、固定用 `｜` 分隔，同时进 PDF 默认文件名。

绕开按钮直接 Ctrl+P **不阻断**：客户按 Ctrl+P 只是想留一张纸，弹「已阻断」会让人以为页面坏了。有存过公司名就带上抬头，没有就只印版本号与工况。

**结果页出口**：最后一块是「把这份工况交给工程师」——把物料、粒度口径、目标产能、前 3 名型号排成一张可复制的表，一个按钮复制到剪贴板，客户自己贴进微信或邮件。这里**没有表单、没有假提交、不留资**：本页只做预选，收了数据却没人接，不如不给。

联系方式目前**留空**（`index.html` 的 `CONTACT = { tel, wechat, mail }`）。三项都为空时页面只出「复制这份工况」按钮，不显示联系方式那一行；要上线自己的电话/微信/邮箱，填这一个常量即可，`tools/test-company.js` 覆盖了这条拼接逻辑。

**注意边界**：

- 排序是启发式加权，不是实验结论。留一交叉验证 Top3 命中率 77.9%（跨站留出 79.7%；见 `docs/案例库回灌-分批迭代报告.md` §4）。
- 案例检索是最近邻，已知案例必然能命中自身，只能证明「可检索」，不等于「排序正确」。
- 案例时间统一是 2020 年那批官网内容的上线批次，不代表近期成交。
- 出现「磨蚀性极强」「防爆强制要求」提示时，那是全局约束，先按它筛掉不合适的机型再看排序。
- 最终选型请工程师复核。

## 本地运行

双击 `index.html` 即可，不需要 `npm install`、不需要起服务器。

## 数据与引擎

- 设备库 48 个系列，分 7 类：分级机 / 气流粉碎 / 机械粉碎 / 改性机 / 球磨分级生产线 / 实验室设备 / 辅助设备
- 物料库 1433 条，含密度、莫氏硬度、含水率、CAS、中英文名与别名
- 成交案例 163 例（ALPA 官网中文站 99 + 英文站 64）
- 打分引擎 v8：源码在 `tools/kb.js` + `tools/fit.js`，打包进 `index.html` 的 `==ENGINE_START== … ==ENGINE_END==` 块。页面和 `node tools/fit.js` 跑的是同一份 `score()`，不会出现「离线一套、页面另一套」。
- 物料行业先验（F 项）v8 起按三档：本类命中 1.0 / 邻类命中 0.7 / 不搭 0.45。邻类表 `CAT_ADJ` 与类别映射 `CAT_TO_VALUE` 以 `index.html` 的常量区为唯一来源，`tools/kb.js` 用 `cut()` 从同一个文件里读，所以线上和离线永远是同一张表。

## 版本历史

### v11（2026-02）

- **结果卡配机型图**：官网样册图洗白底 → 吞掉棚拍水印 → 按主体裁边后 base64 内嵌（33 个族有图，`data/machine-images.raw.json` → `tools/white-bg.py` → `data/machine-images.json` → `tools/build-machine-images.js`）。三件清洗缺一不可：底色若留着棚拍暖白，图上就会在纸色底上压出一块比纸略暗的方块；水印只有 232–250 亮度、饱和度≈0，白平衡洗不掉，得按连通性一起吞；裁边是为了让 18 张留白不同的图在页面上按高度对齐后机器大小可比。
- **参考成交案例**：结果区下方按物料 / 粒度 / 产量做最近邻检索，只列同料（或同料族）案例。
- **删掉编不出来的百分比**：粒度、产能不再给「匹配 83%」这类数，改成直接给设备库里的区间 + 是否需并联；样册没列产能的族写「按物料与细度核定」。百分比只留在卡片角标的排序分上。
- **工况出口只做复制，不做提交**：结果页末尾给一张可复制的工况表 + 一个复制按钮，不收手机号、不做假提交。联系方式常量留空，需要时一行填上。
- **公司名称改成点「导出」才问**：它是给客户看的抬头，不是选型参数，放在表单顶部会让人以为必填。
- **PDF 压到一页 A4**：打印样式按 mm 排版、`@page` 写死纸张，机型图 52mm、卡间距 10mm；导出不含输入区与案例，只有 3 张卡 + 免责声明。
- **Ctrl+P 不再阻断**：v10 用 `beforeprint` 加 `company-missing` 把纸面压成一条阻断说明，实际效果是客户自己按打印时以为页面坏了。现在有存过公司名就带抬头，没有就只印版本号与工况。
- **缩到一页的代价**：机型图 52mm、卡间距 10mm 是用 4 组极端工况（重钙 3000 / 硫磺 8000 / 木粉 10000 / 氧化铝 D50 2µm 500）逐一体测出来的最小值，再压缩会让图小到认不出机型。所以页码上限的保证方式是「卡片内容不涨」——推荐理由仍是单行，一旦往后加字段就会溢出到第 2 页。

### v10（2026-01）

- **导出新增公司名称必填**：未填（含纯空格 / 全角空格 / 制表符）时阻断导出，按钮不弹打印框、只标红提示；绕过按钮的 Ctrl+P 靠 `beforeprint` 给 `body` 加 `company-missing`，纸面只留阻断说明。名称固定以 `｜` 拼在「粉体预选型 v10」之后，同时进 PDF 页眉与默认文件名。
- **修正物料分类映射链**：`CAT_TO_VALUE` 原有 3 个断点（`食品添加剂` 未映射、`塑料/橡胶/胶黏剂` 写成无斜杠的 `塑料橡胶胶黏剂`、`能源` 缺键），15 条物料掉进 `other`、F 项被压到 0.45，典型症状是果胶（食品添加剂）把「TSM 系列碳酸氢钠专用粉碎机」顶进 Top2。现已全部映射，扩 `node tools/audit-cat.js` 自动查断点。新增 `CATV()` 归一化，键名写岔（空白 / 斜杠 / 顿号）不再静默掉类。
- **F 项从两档改三档**：本类命中 1.0 / 邻类命中 0.7 / 不搭 0.45。原来「医药↔食品」「矿物↔固废↔硬质矿物」这类共用产线的邻类，和完全不搭的类同罚 0.45，等于把子集关系当无关。留一 Top3 76.7% → 77.9%。
- **试过但没采用**：
  - 给「新材料」单建一个类别（关键词含“新材料”）——它出现在 30 台设备的 mat 字段里，等于营销口径的 catch-all，会让整库拿到 F=1；实测留一 Top3 从 77.9% 掉到 75.5%，因此 `新材料` 仍归 `other`（F 均匀，不给假信号）。7 条新材料物料（木粉 / 竹粉 / 针状焦 / 荧光粉 / 稀土氧化物等）的正确归属建议按物料逐条改 `cat`，需要业务方定，不在本版自作主张。
  - `高新材料` 改映射到 chem / mineral / battery / waste 任一具体类别：四种都让留一 Top3 掉到 76.7%（这批案例跨塑料、电池、非金属矿、化工四类，任何单类别都是错的先验），保持 `other`。
  - F 项关键词从 `dev.mat` 扩大到并入 `feat` / `oth` / `sell` 文本：留一 Top1 掉 0.6、Top3 无收益，说明设备 mat 字段的「类别清单」写法虽粗但干净，掺进卖点文案反而引入噪声。
  - 邻类档实测是平台区（留一 Top3）：0.45→76.7%、0.55 / 0.6 / 0.7→77.9%、0.8→77.3%、0.9 / 1.0→77.9 但样本内已开始掉（64.6% / 62.6%）。取平台区里的 0.7（邻类打七折），保留「邻类≠本类」的子集关系。
- **已知缺口**：`高新材料`、`dry-grinding`、`electronic` 等 37 例行业标签在体系里没有类别归属，走 `other`（F 均匀、不加偏置）。要改善得给这些标签补 `IND2CLASS` 映射，属于数据待办，不是算法问题。

## 维护

改完源码后必须重新注入，`index.html` 里的三个标记区间禁止手改：

```bash
# 改打分逻辑：先改 tools/kb.js / tools/fit.js，再注入
node tools/build-engine-embed.js          # 写入
node tools/build-engine-embed.js --check  # 只校验（提交前自查）

# 改机型图：先改 data/machine-images.raw.json，清洗后再注入
python tools/white-bg.py                  # 需要 Pillow
node tools/build-machine-images.js        # 写入
node tools/build-machine-images.js --check

# 改案例检索/展示：先改 tools/case-module.js，再注入
node tools/inject-case-module.js
node tools/inject-case-module.js --check

# 改案例数据：先改 data/*.tsv，再编译
node tools/build-cases-embed.js
```

回放验证排序质量：

```bash
node tools/fit.js          # 训练集 + 跨站留出
node tools/fit.js --tune   # 粗网格调参
node tools/fit.js --case 乳糖   # 逐项拆解单个案例的打分
```

提交前跑这三项（都不需要浏览器）：

```bash
node tools/build-engine-embed.js --check    # 引擎块与 kb.js/fit.js 是否同步
node tools/build-machine-images.js --check   # 机型图块与 machine-images.json 是否同步
node tools/audit-cat.js                     # 物料分类映射链（有断点则 exit 1）
node tools/test-company.js                  # 导出弹层里公司名称的校验与拼接回归
```

## 部署

GitHub Pages，从 `3698688050-pixel/powder-equipment-selector` 的 `main` 分支根目录构建，`origin` 即该仓库。
